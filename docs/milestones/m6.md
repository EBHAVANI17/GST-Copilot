# M6: Production Hardening, Operational Reliability & Launch Readiness

What Milestone M6 delivered to GST Copilot: production connection pool tuning, graceful shutdown, defense-in-depth HTTP security headers, CORS origin management, uniform unhandled error protection, and end-to-end launch verification.

---

## 1. Connection Pool Tuning & Graceful Shutdown (ADR 0029)

- **SQLAlchemy Async QueuePool:**
  - Added configurable pool settings in `gst_copilot.config.Settings`:
    - `db_pool_size`: baseline pooled connections (default: `10`).
    - `db_max_overflow`: peak connection bursting capacity (default: `20`).
    - `db_pool_timeout`: queue wait timeout in seconds (default: `30.0`).
  - Activated in `gst_copilot.db.session.get_engine()` with connection pre-pinging (`pool_pre_ping=True`) to purge dead connections gracefully.
- **Graceful Lifecycle Disposal:**
  - In `gst_copilot.api.main.lifespan`, the async database engine pool is explicitly disposed on server shutdown:
    ```python
    await get_engine().dispose()
    ```
  - Eliminates hanging client sockets, leaked pgvector connections, and resource leaks during worker cycling or deployment rollouts.

---

## 2. HTTP Security Headers & Origin Controls

- **Standard Defense-in-Depth Headers:**
  - Applied via request context middleware on all incoming requests:
    - `X-Content-Type-Options: nosniff`: prevents MIME-type sniffing attacks.
    - `X-Frame-Options: DENY`: blocks UI redress and clickjacking attacks.
    - `Referrer-Policy: strict-origin-when-cross-origin`: prevents query string and internal token leakage across origin transitions.
- **CORS Configuration:**
  - Fast, modular `CORSMiddleware` integrated with configurable `cors_origins` (default: `["*"]` for development; restricted in production).
  - Permits standard frontend UI integration and external client integration across origins.

## 3. Unhandled Error Standardization & Request Tracing

- **Global 500 Handler:**
  - Registered global exception handler for unhandled `Exception` instances:
    ```python
    @app.exception_handler(Exception)
    async def unhandled_exception_handler(request: Request, exc: Exception) -> JSONResponse:
        rid = request_id_var.get()
        log.exception("unhandled server exception", extra={"fields": {"request_id": rid}})
        return JSONResponse(
            status_code=500,
            content={"detail": "An internal server error occurred.", "request_id": rid},
            headers={"X-Request-Id": rid},
        )
    ```
  - **Zero Stack Trace Leakage:** Server internals and tracebacks are never exposed to external API callers; all error diagnostics are retained in structured logs correlated by `X-Request-Id`.

## 4. End-to-End Launch Integration Test (`tests/test_e2e_launch.py`)

A unified end-to-end test suite verifying the complete operational surface before release:
1. **Security & Diagnostics:** Verifies `/health` and `/ready` endpoints, latency, and all security headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `X-Request-Id`).
2. **Deterministic Invoice Checking:** Validates single-invoice tax mathematical parity, Mod-36 buyer/seller GSTIN checksums, and place-of-supply rules via `POST /check-invoice`.
3. **Reconciliation & GSTR-3B Table 4:** End-to-end execution of synthetic invoice matching (`POST /reconcile`) generating traceable draft Form GSTR-3B Table 4 returns (`4(A)(5)`, `4(B)(2)`, `4(C)`, `4(D)(1)`, `4(D)(2)`).
4. **Date-Aware Statutory RAG:** Verifies temporal filtering with `as_of` dates preventing citation of future or superseded tax provisions.
5. **Uniform Error Handling:** Validates that unexpected runtime failures return standardized 500 JSON payloads carrying the active request ID.
