# M3: Observability, latency, cost

What M3 added to GST Copilot, with the numbers measured on a laptop (RTX 4050 6 GB,
qwen2.5:3b via Ollama, golden v2: 33 questions).

## Observability

- Every `/ask` is stored in `ask_logs`: question, search query, passages and scores,
  answer, flags (refused, partial, truncated, invalid citations), timings per stage,
  tokens, model, prompt version and config (ADR 0012).
- `POST /feedback` (helpful / not helpful + note) on any answer.
- `python -m gst_copilot.observe --days 7`: usage report with rates, latency per
  stage, time to first token, tokens and cost, and the thumbs-down and refused
  questions to turn into golden questions.
- LLM judge (`evals --judge`, ADR 0014): experimental, not trusted for numbers.

## Latency

| Change | Before | After | ADR |
|---|---|---|---|
| Warm-up at startup, `/ready` waits for it | first question 17 s (model loading) | loading moved to startup (~23 s, once) | 0015 |
| Streaming answers (`POST /ask/stream`) | first word only with the whole answer, ~13 s | first word while the answer is written | 0016 |
| Rerank 10 candidates instead of 20 | rerank p50 1881 ms, ttft p50 3376 ms | rerank p50 850 ms, ttft p50 1.5-2.3 s | 0017 |

Rejected: a 5000-character context cap (context_recall 0.688 -> 0.541).

## Cost (ADR 0018)

2425 prompt + 115 answer tokens per answer on average. Local model: no per-token cost.
The same workload on GPT-5 mini: about 0.84 USD per 1,000 answers; on GPT-5 nano
about 0.17 USD (official prices, 2026-10-26).

## Known gaps

- Answer quality is limited by the 3B model: false refusals (0.14-0.18), missing or
  wrong-section citations, occasional wrong rules (ADR 0009, 0013).
- Retrieval misses q011, q014, q015, q016, q019, q020 at section level.
- Abandoned streams are not logged; the judge is not validated enough to publish.
