# M5: Corpus Freshness, Date-Aware Retrieval & Assistant Safety

What Milestone M5 added to GST Copilot: keeping the statutory knowledge base fresh within a 24-hour SLA, date-aware retrieval filtering across legislative changes, and strict input safety and prompt-injection guarantees.

---

## 1. Notification Watcher & Corpus Freshness (ADR 0024)

- **24-Hour Gazette SLA:**
  - Standardized daily protocol for monitoring official CBIC and GST Council portals.
  - Documents cataloged in `corpus/manifest.csv` with statutory metadata: `issued_on`, `effective_from`, and `effective_to`.
  - Ingestion updates are idempotent: SHA-256 hash checks ensure only new or modified documents are re-embedded.

- **Freshness Reporting CLI & API:**
  - CLI: `python -m gst_copilot.ingest.freshness` reports document count, breakdown by document type, newest document title/date, and days elapsed.
  - Readiness endpoint: `/ready` reports `corpus_date` and `corpus_freshness_days` alongside Postgres/Redis health, while keeping `/health` purely as an unburdened liveness check.
  - Decoupled manifest verification (`check_files=False`): metadata freshness can be verified in containerized and CI environments without requiring raw PDF binaries.

---

## 2. Date-Aware Retrieval (ADR 0028)

GST law is temporal: provisions, thresholds, and administrative relief change over time.

- **Query `as_of` Date:**
  - Added optional `as_of: date | None = None` parameter to `AskRequest` (`POST /ask` and `POST /ask/stream`).
  - Default `None` preserves complete backwards compatibility for undated statutory research.

- **SQL Temporal Filtering:**
  - In `gst_copilot.rag.retriever`, joined chunks are filtered against the target date:
    ```python
    if as_of is not None:
        stmt = stmt.where(
            (Document.effective_from.is_(None) | (Document.effective_from <= as_of))
            & (Document.effective_to.is_(None) | (Document.effective_to >= as_of))
        )
    ```
  - Applied uniformly across pgvector vector search, tsvector keyword search, and reranker candidate pooling.
  - **Result:** Questions about earlier fiscal periods (e.g. FY 2020-21) will not cite future circulars (e.g. Circular 170/02/2022 or Circular 193/05/2023), and superseded rules are excluded from current queries.

- **Observability:**
  - Evaluated target date recorded in `AskResult.as_of` and persisted in `AskLog.config["as_of"]`.
  - Golden evaluation runner (`python -m gst_copilot.evals`) evaluates temporal queries by reading `"as_of"` from `GoldenItem`.

## 3. Assistant Safety & Injection Guarantees (ADR 0025)

- **Input Boundaries & Validation:**
  - Enforced question length limit between 3 and `ASK_MAX_QUESTION_CHARS` (default: 1,000 characters).
  - Pre-trimming validation prevents whitespace-only bypass attacks.
  - Enforced equally on `POST /ask` and `POST /ask/stream`.

- **Hard Structural Guarantees (`tests/test_safety.py`):**
  - **Prompt isolation:** The user question is strictly confined to user messages; it never enters the system prompt.
  - **Context barrier:** Injected delimiter blocks (`CONTEXT: [CGST-ACT#999] ...`) remain in the question text; they cannot inject artificial context passages.
  - **Passage instruction isolation:** Instructions embedded inside retrieved legal texts remain in context and cannot overwrite assistant operating rules.
  - **Citation verification:** Made-up citation tags (`[FAKE-CIRCULAR#1]`) injected in questions are flagged in `invalid_citations`, never marked as cited.

- **Safety Evaluation Suite:**
  - Dedicated `evals/safety.jsonl` framework testing refusals on tax evasion queries, non-GST domain questions, and adversarial jailbreak attempts.
